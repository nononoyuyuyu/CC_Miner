マニュアル / group / discard

P1 / 複数 worker

group、bay、discard を正しく使う

group は controller が保持する worker の集合、bay は物理ドック、group job は共通の範囲を分割した一つの作業です。discard は在庫が逼迫したときの明示的な廃棄ポリシーで、既定は KEEP_ALL です。

group のモデル

項目意味設定・検査
groupIdcontroller DB の durable な集合 ID。worker IDs を重複なしで登録。空 group は fatal。
dockId / bayId物理 dock と bay の識別子。world group は bay 登録と各 worker の home pose／facing を検査。
modeworld または local。複数 worker の partition は world のみ。local group の自動分割は拒否。
partitionchunk を割り当てる方式。既定は stripe。各 worker の own bay chunk から連結する mine/transit lease を作り重複を拒否。
staggerSecondsworker 起動間隔。partial start を避け、ACK/status と scheduler で順に dispatch。
replenishConcurrencygroup 内で同時に service する上限。fuel emergency が優先。bay のチェストを共有しない。
requireSameFloorbay と worker の home floor を揃える安全ゲート。既定有効。world Y／bay pose が不一致なら preflight fatal。

world group の partition

world group のみ、共通の footprint を worker ごとの chunk 割当に分けます。各 assignment は chunkKeys（採掘）と transitKeys（移動）を持ち、自分の bay chunk からの連結と mine/transit lease の両方を preflight します。

group START と失敗時

  1. controller DB に bay と group を登録し、worker IDs、mode、partition、stagger、service concurrency を設定。
  2. 各 worker が online、同一 protocol、home、group capability、GPS CAL 済み（world mode）であることを preflight。
  3. 全 assignment の lease を予約し、stagger に従い groupCommand=START を dispatch。
  4. 一つでも送信に失敗すると PARTIAL_START。開始済み worker へ安全帰還を送り、未開始 lease を解放します。
  5. 稼働中は group aggregate（online、active、complete、blocked、waiting、minFuel、ACK）を確認。停止・帰還は group command でまとめて行います。

停止 worker の残余範囲は、online target へ REASSIGN できます。再割当された assignment と元 worker、時刻を history/report で確認します。

絶対 BOTTOM Y と group

BOTTOM Y は group 全員で共通にする world の絶対 Y 座標です。各 worker は自分の calibrated home Y から、次式で層数を計算します。

layers = homeY - bottomY + 1
bottomY (= targetY) は homeY 以下
深さを worker ごとに変えない。 ある worker の homeY が異なる場合、同じ BOTTOM Y でも layers が変わります。maxDepth を超える worker、homeY 未取得、bottomY が home より上は group preflight fatal です。

local group では絶対 Y を使えず、複数 worker への自動 partition もできません。GPS 任意運用では world group、world 重複検査、BOTTOM Y を選ばないでください。

discard ポリシー

discard は inventory の空きが閾値以下になった境界で、保護されていないスタックだけを扱います。既定 KEEP_ALL は何も捨てません。ore/raw、torch、fuel、seal は常に hard protected です。unknown な mod item は既定と stone モードでは保持し、CUSTOM_ALLOWLIST で正確な完全 item ID（例 mod:item_name）を明示したときだけ候補になります。

mode動作安全条件
KEEP_ALL全 item を搬出へ送り、discard しない。既定。迷ったらこれ。
DISCARD_EXCESS_STONEstone/cobblestone/cobbled_deepslate の余剰を、seal reserve を残して廃棄。seal target（既定 64）を下回らない。1 pass の max stacks（既定 8）を超えない。unknown は保持。
CUSTOM_ALLOWLIST正確な完全 item ID を明示した item だけを廃棄。allowlist は空・wildcard・protected／empty を含めない。ore/raw、torch、fuel、seal は常に保護。unknown mod item も完全 ID を明示しない限り保持。

現場（採掘中）の discard

  • triggerEmptySlots（既定 3）以下で pass を検討し、候補はスタック単位で最大 maxStacksPerPass（既定 8）まで扱います。
  • 設定方向に inventory が見つかった場合は、誤投入防止のため現場 discard を安全に skipし、stack を保持します。
  • inventory がない方向では候補スタックを world へ drop します。これは不可逆です。drop 失敗時は stack を残し lastError を記録します。

ホーム unload の discard

  • discard direction が output と異なる場合、そこに inventory が存在することを検証します。
  • configured discard inventory が無い・満杯・保護 stack を保持できない場合は discard_inventory_error／waiting として停止し、home から無理に進みません。
  • report の discard、discardedBlocks、discardSkipped、discardUnknown を確認します。
廃棄は不可逆。 valuable、fuel、torch、seal、protected block を allowlist に追加しないでください。unknown mod item は完全 ID を確認してから指定します。最初は KEEP_ALL で小さい job を試します。

group 登録と preflight 制約

controller の CLI は 1 つの管理 dock、worker ごとの bay、group の順に登録します。dock は複数チャンクにまたがる管理アンカー、bay は各 worker の帰還入口です。座標は整数、facing は front/south=0、right/east=1、back/north=2、left/west=3（または 0〜3）、maxDepth は正の整数です。

ccm dock register dock-a 100 64 100 east 64
ccm bay register bay-a 100 64 100 east 64
ccm bay register bay-b 116 64 100 east 64
ccm group register quarry-a 101,102 QuarryA dock-a bay-a world stripe 101=bay-a,102=bay-b 101=dock-a,102=dock-a

group 構文は ccm group register <id> <workerIds comma> [name dock bay mode partition workerBayMap workerDockMap]。末尾の map は workerId=resourceId,...（空白なし）で、workerBays と workerDocks を worker ごとに対応づけます。map キーは group の worker ID に限り、値は登録済みリソース ID にします。省略時は単一 worker／local の既定 dock/bay を使えますが、world group は各 worker の own bay／dock map を明示しないと重複 preflight で開始できません。

  • own bay chunk： 各 worker の GPS home と正面 1 ブロック先は同じ自分の bay chunk に入り、worker 間の bay chunk は一意。全 bay chunk は共通 job footprint 内で、own assignment の mine/transit lease と帰還経路を分離します。
  • same floor： 既定 dock.requireSameFloor=true。登録 bay の Y と GPS calibrated HOME Y を揃え、BOTTOM Y の計算基準を同じ階にします。
  • orientation： 登録 bay の facing と各 GPS CAL の forward が group 内で一致。front/east などの取り違えは fatal。
  • spacing： bay chunk が重ならないことに加え、登録 bay の X/Z ユークリッド距離（sqrt(dx²+dz²)）を既定 baySpacing=4 以上にします。例の (100,64,100) と (116,64,100) は別 chunk かつ距離 16 です。

ccm dock list、ccm bay list、ccm group list／show <id> で保存値を確認し、GROUPS が空なら登録を先に完了します。

group / discard のレポート

ccm report と dashboard の report/history では group、groupJobId、BOTTOM Y、discard、throughput、last return を確認できます。group job は assignment ごとの状態と aggregate が残りますが、外部倉庫の実際の一度だけ処理までは証明しません。

group job のタッチ画面と復帰

GROUPS は WORKER GROUPS 画面、G START は GROUP JOB / DIMENSIONS 画面、DRILLDOWN は GROUP DRILLDOWN 画面を開きます。前者で group を選択し、寸法・world の絶対 BOTTOM Y・partition を preflight してから START。DRILLDOWN では assignment、HOME Y、LAYERS、残余 chunk、ACK、RETURN reason、discard/metrics を確認します。

停止 worker の残余を REASSIGN すると、source が terminal かつ home、resume token（groupJobId・assignment・world pose）が整合し、target が idle/terminal・home・（world なら）GPS 校正済みのときだけ受理されます。target は自分のホーム → 自分の bay/dock chunk → resume checkpointへ移動し、GPS と向きを検証して own assignment の残余を再開します。token 不在・不一致、bay/dock pose 不一致、他 worker と同じ bay chunk は安全拒否です。

経路の分離。 管理 dock は複数チャンクにまたがっても、各 worker は一意な own bay chunk と own mine/transit assignment を使います。初回 START と帰還／再開はこの assignment 境界で分離し、他 worker の bay chunkへ依存しません。
