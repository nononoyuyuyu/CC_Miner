困ったとき

画面に出た言葉と同じ見出しを探し、上から順に確認してください。直るまでタートルを手で動かさず、設定や記録を消さないでください。

最初にすること

  1. 表示を写真やメモに残す

    エラーの最初の行と、ファイル名・行番号があれば一緒に残します。

  2. 状態を見る

    ccm status
ccm doctor
ccm logs

  3. タートルの位置を変えない

    置き場、向き、チェスト、持ち物を見て、画面の状態と比べます。

セットアップ画面が「????」になる

CC:Tweakedのゲーム内画面は日本語を表示できません。古い版のセットアップに日本語が入っていたため、文字がすべて「?」になっていました。最新版ではゲーム内表示を短い英語だけにしています。

  1. 今のセットアップは Ctrl と T を長押しして終了します。
  2. 最新版へ更新します。
  3. ccm setup worker または ccm setup controller をもう一度実行します。
  4. 詳しい意味は、この日本語HTML手順書の設定を変えるで確認します。

採掘タートルが見つからない

  1. 無線モデムを見る

    採掘タートルと管理用コンピューターの両方に無線モデムが必要です。起動後に付けた場合は両方を再起動します。

  2. 合言葉を見る

    両方の networkKey を完全に同じにします。大文字・小文字、空白も確認します。

  3. 古い管理番号の固定を外す

    以前の管理用コンピューターを使っていた採掘タートルは、controllerIdを0にするか、今の管理用コンピューターの番号にします。

  4. 同じ版へ更新する

    片方だけ古いと通信を安全のため拒否します。両方を同じ版へ更新し、再起動します。

  5. 探し直す

    ccm discover

history database not found

まだ完了した採掘作業がなく、履歴ファイルが作られていない場合に出ることがあります。採掘タートルの接続や採掘そのものの失敗ではありません。

  1. まず ccm dashboard で採掘タートルが見えるか確認します。
  2. 小さな採掘作業を1回完了させます。
  3. 完了後に ccm report をもう一度開きます。

startup.lua:4: <eof> expected near 'end'

古い版で、起動用ファイルの改行が足りずに作られたときのエラーです。最新版では修正されています。

  1. いったん直接起動する

    /ccminer/boot.lua

  2. 最新版へ更新する

    更新手順を実行します。

  3. まだ直らない場合

    edit /startup.luaで開き、最小の2行を次のようにします。

    -- CC_MINER_V2_STARTUP
shell.run("/ccminer/boot.lua")

  4. 再起動する

    reboot

Serialize failed / cannot serialize table

古い版で、同じ表を二重に保存しようとしたときに出たエラーです。最新版では、保存する内容を分けてから書き込むよう修正されています。

  1. 管理用コンピューターと採掘タートルを最新版へ更新します。
  2. 両方を再起動します。
  3. 同じ作業を新しく作り直します。古い作業が残っている場合は、状態を確認してABORTしてからCLEARします。

Cannot back up existing installation / Out of space

古いプログラムの控えを作る空き容量がありません。古い /ccminer を削除しないでください。

wget run https://raw.githubusercontent.com/nononoyuyuyu/CC_Miner/main/install.lua update-low-space

途中で止まった場合は、少し空きを作り、同じコマンドをもう一度実行します。

初回の install.lua worker、install.lua controller、install.lua gps でこの表示が出た場合は、最新版で初回インストールも省容量方式になっています。最初に入力したものと同じコマンドを、もう一度実行してください。

[1/13] lib/common.lua ... FAILED / Staging verification failed

通常更新が作る一時コピーの空き容量不足、または古いCC環境で保存時に文字データが変換された状態です。空きが十分あるのに「expected」と「wrote」がほぼ同じ大きさなら、文字変換が原因です。最新版は取得・保存・再読込をバイナリ方式に統一し、正確なバイト数を表示します。空き容量が本当に不足している場合だけ、省容量更新へ自動で切り替わります。

  1. 最新版の install.lua update をもう一度実行します。
  2. Switching automatically to update-low-space mode と表示されたら、そのまま待ちます。
  3. 古い /ccminer、設定、作業記録は手で削除しません。
  4. 古いインストーラーのままなら、上の update-low-space コマンドを直接実行します。

プレフライトは緑なのに採掘せず、次のSTARTが灰色になる

古いV4コントローラーが、1台だけの通常採掘へグループ採掘用の番号を付けて送り、ワーカーが安全のため拒否していた問題です。拒否後の採掘範囲予約も残るため、同じ範囲のSTARTが灰色になっていました。

  1. コントローラーとワーカーを最新版へ更新し、両方を再起動します。
  2. 管理画面でDISCOVERを押し、ワーカーの状態を受け取ります。
  3. 最新版は、採掘を始めていないワーカーに残った古い予約を自動で片付けます。
  4. もう一度NEW JOBから範囲を選び、プレフライトの「start state」「home」「facing」「recovery」「existing job」を確認してSTARTを押します。

GPSは通常の1台採掘には必須ではありません。GPSなしでは、ドックを基準に「下へ何層掘るか」をDEPTHで指定します。絶対Y座標のBOTTOM Y、ワールド座標のチャンク選択、複数ワーカーへの範囲分割を使う場合だけGPSが必要です。

拒否理由は画面下へ赤字で残りますが、ほかの操作は続けられます。全文を読むときだけ管理画面の「LAST ERR」を押し、確認後にOKで戻ります。GPSを使う作業で GPS calibration と表示された場合は、採掘タートルをドックへ置き、正面を空けて、管理画面のGPSから一度だけ校正してください。

タートルをクリックしても文字を入力できない

採掘タートルの画面がプログラムに使われている間は、通常の入力行が出ません。管理用コンピューターから操作するのが正常です。

  1. 採掘中なら管理画面からPAUSEまたはRETURN HOMEを選びます。
  2. 止まるまで待ちます。
  3. 設定を変えるなら管理画面またはセットアップを使います。
  4. 故障調査でどうしても終了する場合だけ、CtrlとTを長押しします。安全処理中は終了を受け付けないことがあります。

最新版では通信待ちやGPS確認中でも、CtrlとTの長押しを終了操作として扱います。Worker stopped locally. と表示され、通常の入力行へ戻ります。再開するときは reboot を入力します。

FUEL / TORCHES / GPS に !! が出る

表示意味確認すること
FUEL !!必要な燃料を確認できない、または足りない上面チェスト、燃料にできる物、残量。十分なら再度開始前チェック。
TORCHES !!たいまつを使う設定なのに在庫が足りない、または確認できない照明OFFなら0で正常。使うなら左面チェストと許可したたいまつ。
GPS !!GPSの位置が取れないGPSを使わない作業なら注意だけ。使うなら4台、モデム座標、無線距離、GPS CAL。

しょっちゅう置き場へ戻る

SAFEは早めに戻るため、最小構成では正常な場合があります。ただし数分ごとに同じ理由で戻るなら、REPORTを見ます。

  • 燃料：上面チェストの量と燃料の種類を確認
  • 持ち物：搬出チェストの空き、不要な石の処分を確認
  • たいまつ：左面チェストと間隔を確認
  • 穴埋め材：右面チェストと掘った石の再利用を確認

1回成功したあとでSAFEからBALANCEDへ変更すると、帰還回数を減らせる場合があります。

位置が分からない・電源が落ちた

  1. 手で動かさない

    今いる場所、向き、周りのブロックを記録します。

  2. RECOVERYを開く

    管理画面の復旧案内に従います。GPSがある場合は位置の一致を確認します。

  3. 置き場へ戻す必要がある場合

    画面の指示が出たときだけ、元の置き場へ同じ向きで置きます。

  4. REHOME RESETは最後

    これは作業と再開情報を消します。続きから再開できないと判断した場合だけ、二段階の確認後に使います。
