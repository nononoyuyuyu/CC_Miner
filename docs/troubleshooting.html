マニュアル / トラブル切分け

P0 / first response

停止理由から順に切り分ける

最初に dashboard の worker 行、preflight、ccm logs、report を保存します。原因が不明なまま REHOME RESET を押すと job と復旧情報を消すため、wizard を先に読みます。

空き容量不足の更新

Cannot back up existing installation / Out of space。 旧 /ccminer を削除せず、空きを少し確保して low-space update を実行します。

オンライン（role 自動判定）

wget run https://raw.githubusercontent.com/nononoyuyuyu/CC_Miner/main/install.lua update-low-space

オフライン（role loader）

ccminer-offline-worker.lua update-low-space
ccminer-offline-controller.lua update-low-space
ccminer-offline-gps.lua update-low-space

途中で電源断・容量不足になると /ccminer.update.low-space.marker（version／role／next／phase の serialized marker、.tmp／.bak atomic fallback）が残ります。空きを確保し、同じ role のコマンドを再実行します。オフライン role loader は既存 config.role が basename の role と一致するときだけ更新し、loader が組立・検証後に parts を削除するため、原本の role loader／parts は PC／外部媒体に保持し、失敗時は一式を再転送してください。marker がある間は通常 ccm update を実行せず、/ccminer や data/ を手で削除しません。

worker が見つからない／offline

  1. worker/controller の network key と protocol version が一致。
  2. Wireless Modem が装着・起動し、距離、遮蔽、dimension を確認。
  3. ccm discover と worker log の modem 起動を確認。
  4. controller timeout、worker atHome、group capability を確認。
  5. オフライン導入直後なら、role loader と同名 parts の対を転送したか確認。loader 成功後は parts が自身で削除されるため、再導入時は PC／外部原本から再転送。
  6. chunk load は CC Miner から確認できないため、サーバー／Modpack 管理者の手順で別確認。

waiting_* の意味

waiting_output

worker 背面搬出の空き、側面、経路を確認。Wired source 仕分けの満杯とは別。

waiting_fuel

真上 fuel chest の燃料だけを補充。帰還距離 + profile margin を満たして RESUME。

waiting_seal

右（既定）の seal chest に許可固体を補給。torch chest（左）と混同しない。

waiting_torch

専用 torch chest、slot、niche 面、SAFE/BALANCED/TURBO 間隔を確認。

GPS drift／fix timeout

  • 4 host が gps host で起動し、Wireless Modem 座標が正しい。
  • worker の CAL が calibrated、home Y と facing が期待値。
  • host と採掘地点の chunk がロードされ、通信距離内（ロード状態は管理者側）。
  • GPS required は fix が得られるまで START／RETURN／RESUME を押さない。
  • GPS optional は local にフォールバックするが、world queue／BOTTOM Y／world overlap は使えない。

recovery wizard と REHOME

  1. 停止理由、last confirmed pose、pending action、journal path、lastReturn を記録。
  2. 手動移動の可能性があればタートルの電源を切り、元のドックへ戻し正面を合わせる。
  3. GPS fix とチェスト／在庫を確認。旋回中・fix 不能は自動解決しない。
  4. 画面の REHOME RESET を二段確認。これは active job を消去する。
  5. job を保持して RESUME、または ABORT して report を保存。
state_corrupt。 .bak、journal、logs を保存してからバックアップ手順へ。空の job を新規開始して上書きしません。

group／discard の切分け

  • group は worker IDs、dock/bay、world mode、partition、stagger、service concurrency を確認。
  • PARTIAL_START は開始済みを safe return し、lease を再確認してから再 START。
  • residual range の REASSIGN は online worker を選び、groupJobId と assignment を記録。
  • discard は既定 KEEP_ALL。現場方向が inventory なら安全 skip、inventory がなければ候補 stack を world drop。ore/raw、torch、fuel、seal は hard protected。unknown mod item は既定／stone mode では保持し、CUSTOM_ALLOWLIST で正確な完全 item ID を明示した場合だけ候補。
  • ホーム unload で discard direction の inventory が無い場合は discard_inventory_error で停止するため、専用 chest を用意。
  • report の group、BOTTOM Y、discard、throughput、return を保存し、外部 inventory の二重処理と混同しない。
