マニュアル / 安全設計

P0 / fail-safe

開始前に拒否し、迷ったら停止する

Modpack 固有の block、fluid、inventory、仕分け、チャンクロードを安全だと仮定しません。preflight で fatal を止め、物理操作の前後を state と journal に保存し、判断できない状態は waiting または recovery wizard にします。

preflight の拒否規則

分類例結果
fataloffline、invalid、connectivity、capability、lease、GPS required、world overlap、group pose、BOTTOM Y。START／QUEUE／group START を無効化。
warningfuel、seal、torch、stock unknown、dock metadata unavailable。補給を前提に続行可能。ただし実行中に waiting_* へ移行。
OKLIGHT OFF、local GPS、十分な fuel、連結・保護 block 検査。次のチェックへ進む。

world lease は active／queued の X/Z（および mine/transit）重複を拒否します。local の異なる worker や手動採掘との重複は検知できません。単一 footprint の自動分割は group world partition を除いて行いません。

水・溶岩の封鎖

lavaMode=seal、waterMode=seal では進行方向・上・下の流体を許可された固体 block で封鎖します。stop はその場で停止。continuous seal の上限は min(worker 絶対上限, profile cap)（SAFE 8 / BALANCED 32 / TURBO 64）です。

  • 砂、砂利、TNT、バケツ、可燃物、液体を seal 材にしない。
  • turtle.place* が失敗したら流体へ移動しない。
  • 材料不足、許可リスト外、チェスト空、上限超過は waiting_seal または blocked。
  • Mod 追加 fluid の名前・流れ方は小さい試験区画で確認。

たいまつと保護

torch は seal 側の反対にある専用 chest（既定 seal=右、torch=左）から補給します。SAFE は間隔最大 8、BALANCED は設定値（既定 10）、TURBO は 12。通常の 1×1 坑道では左右 niche の安全面だけを使い、両側が塞がる・指定面が危険・torch 不足なら停止します。custom floor fallback の失敗は非致命です。

Bedrock、Portal、Computer／Turtle、設定済み protected block、inventory を持つ block は掘りません。Mod 追加の重要 block は protectedBlocks に明示します。採掘石の seal 再利用は許可名だけ、保持上限を超えた分は discard／搬出ポリシーへ渡します。

state.db、journal、checkpoint

/ccminer/data/state.db と .bak が正本です。journal は補助で、maxEntries、size rotate、checkpoint を使います。unloading、waiting_fuel、waiting_output、waiting_seal、waiting_torch の境界と保留操作を保存し、次回 load でチェスト・在庫・姿勢を再検証します。

state と姿勢が矛盾する場合。 空の job として再開せず、wizard で停止します。journal を state.db の代替として手編集しません。

電源断と GPS

GPS 校正済みなら移動・採掘・設置の前後座標から pending action を解決できる場合があります。旋回、GPS CAL、fix 不能、手動移動後の drift は自動解決せず、recovery_required へ移行します。GPS required は fix が得られるまで開始・帰還・復帰しません。

  1. 画面の停止理由、最後の確定座標、保留操作、lastReturn を記録。
  2. タートルをピストン、レンチ、プレイヤーで動かさず、電源を切ったまま home へ戻す。
  3. チェスト、fuel、seal、torch、modem、GPS host を確認。
  4. 必要なら GPS CAL。REHOME RESET は job を消去する二段確認。
  5. job を保持して RESUME、または ABORT して report を保存。

通知・仕分けの安全境界

speaker／redstone は完了、停止、待機、復旧要求を知らせるだけ。Wired Modem 仕分けは controller の source→valuable／bulk／seal push で、満杯・切断中は残留して次 tick retry。外部装置の二重処理、認証、監査、権限分離は保証しません。

明確な非対応

chunk load

チャンクロード状態の取得・表示・自動化、chunk loader の設置はしません。

管理者機能

管理者権限、認証基盤、強い暗号化、外部 job の重複検出はありません。

未知の環境

Mod 追加 block／fluid／inventory の安全性は推測せず、保護リストと試験 job を使います。
