P0 / 導入

オンライン・オフライン導入と更新

役割ごとに installer を一度だけ実行し、worker と controller の network key を一致させます。GPS は必要なときだけ 4 台以上を導入します。更新前に world と設定をバックアップしてください。

オンライン導入

HTTP が許可されている Computer で、各役割を実行します。

役割コマンド完了後
worker
wget run https://raw.githubusercontent.com/nononoyuyuyu/CC_Miner/main/install.lua worker
Wireless Modem、名前、network key、GPS 任意／必須を設定。
controller
wget run https://raw.githubusercontent.com/nononoyuyuyu/CC_Miner/main/install.lua controller
同じ key、controller 名、monitor／touch を設定。
GPS host
wget run https://raw.githubusercontent.com/nononoyuyuyu/CC_Miner/main/install.lua gps
4 台以上を起動し、各無線モデムの world 座標を入力。

URL の到達性、HTTP 許可、GPS 通信距離はサーバー／Modpack の設定です。

オフライン導入と通常更新

役割ごとの loader と同名の parts ディレクトリ（parts は 01.part のような 2 桁連番、各 12,000 B 以下）を、対になったまま PC／外部媒体から転送します。

dist/ccminer-offline-worker.lua      + dist/ccminer-offline-worker.parts/
dist/ccminer-offline-controller.lua  + dist/ccminer-offline-controller.parts/
dist/ccminer-offline-gps.lua          + dist/ccminer-offline-gps.parts/

loader の basename が role を決めるため、worker／controller／gps を取り違えません。loader は自身の parts を組み立てて Lua 構文を検証し、1 MB 制限内で空きを確保するため、成功後に自身の parts を削除します。原本の loader／parts は PC／外部媒体に保持し、組立・検証失敗時は同じ role の一式を再転送してください。loader は引数なしなら basename の role を使い、明示する場合は worker／controller／gps を渡します。

role loader の導入は次の構文です（引数を省略しても basename の role を使用）。

ccminer-offline-worker.lua worker\nccminer-offline-controller.lua controller\nccminer-offline-gps.lua gps

互換 dispatcher も残ります。

ccminer-offline.lua worker
ccminer-offline.lua controller
ccminer-offline.lua gps
ccminer-offline.lua update

オンラインの通常 update は install.lua update だけを指定し、既存 config.role から role を自動判定します。role 引数を追加する場合も config.role と一致しなければ拒否します。オフライン role loader は update だけを指定し、既存 config.role が loader の role と一致する場合だけ更新します。旧 /ccminer をバックアップしてから入れ替えます。設定、state、checkpoint、journal、logs は保持されますが、更新前のバックアップを別に確保してください。

空き容量が少ない場合（low-space update）

通常 update のバックアップに失敗したら、旧 /ccminer を削除しない。 少し空きを確保し、low-space コマンドを使います。

オンライン（role 自動判定）

wget run https://raw.githubusercontent.com/nononoyuyuyu/CC_Miner/main/install.lua update-low-space

オフライン（role loader）

ccminer-offline-worker.lua update-low-space
ccminer-offline-controller.lua update-low-space
ccminer-offline-gps.lua update-low-space
  1. runtime ファイルを一時領域へ全て取得し、Lua 構文を検証します。
  2. ユーザーデータ（config.db、data/state.db、checkpoint、journal、logs）をコピー・削除せず、1 ファイルずつ反映します。
  3. 電源断・容量不足なら /ccminer.update.low-space.marker（version／role／next／phase の serialized marker、.tmp／.bak atomic fallback）を残します。空きを確保し、同じ role loader の low-space コマンドを再実行すると marker の位置から再開します。online の role 引数を指定する場合は config.role と一致させます。
marker がある間。 通常の ccm update を再実行せず、表示された low-space コマンドを使います。再実行または復旧が終わるまで /ccminer を手動編集しません。runtime が途中状態で停止する可能性があります。

セットアップ項目

worker

  • network key、worker 名、GPS enabled／required、fix timeout
  • SAFE / BALANCED / TURBO、燃料目標、帰還 buffer、空き slot
  • lavaMode / waterMode（seal / stop、水は ignore 可）
  • seal 側（既定右）、反対側の専用 torch（既定左）、許可 block、予約 slot
  • 保護 block、移動 retry、state journal、speaker／redstone（任意）

controller

  • worker と同じ key、controller 名、monitor 倍率、touch
  • job preset、history、queue 上限
  • world 重複検査（GPS 使用時）、通知、Wired source／destination

GPS host

  • ホスト名
  • 無線モデム block の world X/Y/Z
  • 4 台以上、異なる高さの立体配置、同一 dimension

導入直後のチェック

  1. ccm discover で worker が見える。
  2. 搬出・燃料・seal・専用 torch のチェストを左右の決めた側へ置く。
  3. GPS を使う場合は GPS CAL を実行。
  4. 小さい NEW JOB で preflight と見積を確認。
  5. 通知・仕分けを使う場合は停止通知と source→valuable／bulk／seal push を試す。
中断した setup。 画面に表示された /ccminer/setup.lua <role> を実行して完了後に reboot します。

controller registry の初回登録

複数 worker を world group で動かす場合、setup の後に controller 端末で 1 つの管理 dock と、worker ごとに独立した bay を登録します。dock は複数チャンクにまたがる管理アンカー、bay は各 worker の帰還入口です。座標は整数、facing は front/south=0、right/east=1、back/north=2、left/west=3（または 0〜3）、maxDepth は正の整数です。

ccm dock register dock-a 100 64 100 east 64
ccm bay register bay-a 100 64 100 east 64
ccm bay register bay-b 116 64 100 east 64
ccm group register quarry-a 101,102 QuarryA dock-a bay-a world stripe 101=bay-a,102=bay-b 101=dock-a,102=dock-a

ccm group register の末尾 2 引数は workerId=resourceId,... 形式の workerBays、workerDocks map（空白なし）です。ccm dock list、ccm bay list、ccm group list と ccm group show quarry-a で登録を確認してから dashboard を再表示します。各 worker の home と正面 1 ブロック先は同じ自分の bay chunk に入り、worker 間の bay chunk は一意、全 bay chunk は job footprint 内、same-floor と orientation が一致する必要があります。baySpacing の preflight と map の詳細は group 登録 と ドック登録を参照してください。
