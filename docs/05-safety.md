# 5. 安全設計と制約

## 実装している安全機能

### 状態の二重保存

設定とワーカー状態は、本体ファイルと `.bak` の2世代で保存します。書き込み時に一時ファイルを使い、完全な旧版を残してから新しい状態へ切り替えます。

対象:

```text
/ccminer/config.db
/ccminer/config.db.bak
/ccminer/data/state.db
/ccminer/data/state.db.bak
```

### 物理動作ジャーナル

回転、移動、採掘の直前に `pendingAction` を保存し、成功後に座標とともに解除します。

電源断が物理動作の瞬間に発生すると、タートルが「動いたか、動かなかったか」をソフトウェアだけで断定できません。その場合は自動継続せず、`blocked / recovery_required` で停止します。これにより、誤った座標で採掘を続けることを防ぎます。

### インベントリ満杯前の帰還

標準設定では空きが3スロット以下になると帰還します。さらに、実際にブロックを掘る直前に空きスロットを確認し、空き0なら掘りません。

### 地面への投棄防止

搬出前に、対象面が汎用インベントリまたは安全に識別できるチェスト類であることを確認します。搬出先がない場合は `waiting_output` となり、アイテムを空中へ捨てません。

### 燃料検証

燃料は1個ずつ吸い込み、`turtle.refuel(0)` で有効性を検査してから消費します。非燃料は箱へ返し、`waiting_fuel` で停止します。

### 帰還燃料の予約

現在地からホームまでのマンハッタン距離とバッファを比較し、燃料が危険域へ入る前に帰還します。補給時は、チェックポイントへの往路、再度ホームへ戻る復路、運用バッファを満たす値を計算します。

### 溶岩停止

標準設定は `stopOnLava=true` です。直接進入しようとしているブロックが溶岩と判定された場合、掘らずに停止します。

### 保護対象

Bedrock、ポータル、ComputerCraftのコンピュータ／タートル、汎用インベントリとして認識できるブロック、名前にChest・Barrel・Drawer・Crate・Vault等を含む保管ブロックを掘りません。

### エンティティ非攻撃

標準設定は `attackEntities=false` です。生物が経路を塞ぐ場合、一定回数待ってから安全停止します。

## 人が守る必要がある制約

### ジョブ中にタートルを動かさない

ピストン、Contraption、CreateのMechanical Piston、プレイヤーによる破壊・再配置などでタートルを移動すると、内部座標と現実座標が一致しなくなります。

ジョブ中は次を禁止します。

- 壊して持ち運ぶ
- 向きを変えて置き直す
- ピストンやContraptionで動かす
- 搬出・燃料チェストと位置を入れ替える
- ホーム前の座標基準を変更する

### チャンクをロードする

タートルは、アンロードされたチャンク内で自律動作を続けられません。プレイヤーが近くにいる、またはサーバで許可されたチャンクローダーを使うなど、ホームから採掘範囲までロード状態を維持してください。

長距離クアリーでは、ホームだけでなく移動先のチャンクも対象です。

### 無線範囲

通常Wireless Modemには通信距離があります。距離、遮断、ディメンション、サーバ設定によりワーカーがコントローラから見えなくなる場合があります。

通信が切れても、既に開始済みの採掘はワーカー単独で継続します。ただし遠隔停止は届きません。

### Rednetは暗号化ではない

ネットワークキーは、別のCC Minerシステムとの混線や偶発的なコマンドを避けるための共有文字列です。Rednet自体は盗聴、なりすまし、リプレイに対する強固なセキュリティを保証しません。

信頼できないプレイヤーがComputerCraftを使えるサーバでは:

- 推測しにくい長いキーを使う
- キーをチャットや看板へ書かない
- 必要ならワーカー設定の `controllerId` を特定コントローラIDへ固定する
- 重要設備を保護プラグインや権限で守る

### 流体と重力ブロック

砂・砂利は掘った後に落下するため、同じセルで複数回掘る場合があります。水やMOD流体はブロック状態により挙動が異なります。

溶岩検出は「次に直接入るブロック」が対象です。横から後で流れ込む流体、MOD独自の液体、流体を含む特殊ブロックを完全に封じるものではありません。

### 採掘できないブロック

権限保護、ツールレベル不足、MODの破壊不能ブロック、請求領域などは `blocked` になります。無理に再開を連打せず、詳細画面または `ccm logs` で原因を確認します。

## 再起動時の動作

通常の再起動では、保存済み状態から次を継続します。

- 採掘セルと向き
- 自動帰還
- 搬出待ち
- 燃料待ち
- チェックポイントへの復帰
- Recall後のホーム一時停止

物理動作の直中に停止した記録がある場合だけ、座標不確定として自動継続しません。

## 更新の安全性

オンライン・オフライン更新は、まず新コードを一時ディレクトリへ展開し、すべてのLuaファイルを構文検査します。成功した場合だけ `/ccminer` を入れ替えます。

旧コードは `/ccminer.backup` に残ります。設定、状態、ログは新コードへコピーされます。

## 設定値

通常は `ccm setup` で変更してください。主な初期値:

| 設定 | 初期値 |
|---|---:|
| `fuelTarget` | 12000 |
| `fuelBuffer` | 256 |
| `reserveEmptySlots` | 3 |
| `moveRetries` | 20 |
| `moveRetryDelay` | 0.4秒 |
| `heartbeatSeconds` | 2秒 |
| `stopOnLava` | true |
| `attackEntities` | false |
| 最大幅 | 128 |
| 最大長さ | 512 |
| 最大深さ | 128 |
| 最大体積 | 2,000,000セル |

最大寸法は安全上の入力制限です。サーバ性能、チャンクロード、燃料、ストレージ容量を考え、小さく分割する方が管理しやすくなります。
