マニュアル / 概要・優先度

P0 / P1 / P2

全体設計と機能の境界

CC Miner は「開始前に拒否し、物理操作の前後を保存し、判断できないときは停止する」ための遠隔クアリーです。worker は Advanced Mining Turtle、controller は Advanced Computer、GPS は任意の補助役です。

構成要素

worker

preflight、移動・採掘、たいまつ、液体 seal、搬出、補給、journal、復旧 checkpoint を担当します。ホームをローカル (0,0,0)、正面 +Z、右 +X、下 -Y とします。

controller

worker を discover し、dashboard を端末／Advanced Monitor に描画します。job、chunk grid、preflight、queue、history、report、ACK/status retry を管理します。

GPS host

Computer で gps host を起動する任意役割です。4 台以上を立体配置し、校正すると world chunk、絶対 BOTTOM Y、電源断の移動判定を使えます。

P0 / P1 / P2 機能表

優先度は運用上の分類です。P2 でも無効化されている機能（例：chunk loader 自動化）は提供しません。

優先度含む機能開始条件・注意
P0 コア安全local job、1 タイル = 1 chunk の grid（個別／RECT／ALL／CLEAR／INVERT）、入口固定、preflight、連結 DFS、serpentine、搬出・燃料補給、段階停止、state.db／.bak、journal、復旧 wizard、report。offline／invalid／connectivity／capability／lease は fatal。stock 不足は補給前提 warning。単一 footprint の自動分割は拒否。
P1 位置・資材4 台以上 GPS、world queue、絶対 BOTTOM Y（targetY）、照明（SAFE/BALANCED/TURBO）、水／溶岩 seal/stop、採掘石の seal 材再利用、専用左右チェスト。GPS 必須設定は fix が得られるまで開始・帰還・復帰しない。GPS 任意時は local にフォールバックし world 重複検査を使わない。
P2 運用補助プリセット、queue dispatch、複数 worker の非重複独立 job、history、speaker／redstone、Wired Modem の source→valuable／bulk／seal、adaptive service、render cache、stack compression。ACK/status は再試行するが外部装置の二重処理を保証しない。満杯の送出先は残留して次 tick に retry。chunk load の取得・表示・自動化は対象外。

ジョブのライフサイクル

  1. 作成：寸法、profile、液体、照明、chunk 選択、通知を入力。world queue の targetY は GPS world のみで、depth = homeY - targetY + 1。
  2. preflight：接続、入力、連結性、capability、lease、GPS、保護ブロック、重複、燃料・seal・torch を検査。
  3. 見積：セル数、体積、移動・旋回、補給回数、燃料、seal、torch を表示。Mod 追加の迂回・液体分岐・仕分け待ちは実績との差になる。
  4. 実行：許可 chunk の内部を蛇行し、除外時は DFS の許可辺だけを移動。操作前後の状態と journal を保存。
  5. 停止・サービス：即時、行末、層末、帰還、中止を指定。unloading／waiting_* で停止しても checkpoint から再検証して再開。
  6. 完了・復旧：report と history を保存。旋回中、fix 不能、位置不一致、壊れた state は自動で続行せず wizard を要求。

座標と入口

ホーム基準の座標軸

−Y（下）

ホーム (0,0,0) から、幅は右（+X）、長さは前（+Z）、深さは下（-Y）。入口 chunk は常に固定で、部分 chunk はありません。

テキスト代替：タートルの正面が +Z、右手側が +X、足元方向が -Y。world 座標は GPS 校正後だけ表示できます。

永続化と通信

/ccminer/data/state.db（および .bak）が正本です。journal は maxEntries／size rotate／checkpoint で補助し、state と姿勢が矛盾したときに空 job として再開しません。メッセージには protocol、schema、version、network key、送受信元、message ID を含め ACK/status を保持します。network key は暗号化や強い認証ではありません。

runtime の mining walk は復旧可能な DFS の親情報を保持し、optimizedWalk は計算結果・見積互換として保持します。補給・帰還と checkpoint 復帰の shortestServiceRoute だけが BFS で chunk path を求めます。いずれも chunk 間 transition、保護確認、checkpoint を省略するものではありません。

明示しないこと。 CC Miner は管理者権限、監査ログ、認証基盤、チャンクローダーの検出・制御を提供しません。外部 job、手動採掘、異なるドックの local 範囲の重複も判定できません。
