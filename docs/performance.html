マニュアル / 性能と見積

P2 / performance

速くする場所、速くしない場所

高速化は経路の安全条件と帰還保証を保ったまま行います。単純な見かけの速度より、throughput、return distance、補給回数、停止理由を report で比較してください。

経路ごとの速度

状況経路・最適化安全境界
除外なし通常の serpentine を高速化。各行を一度ずつ通る。入口、層末、行末、帰還の checkpoint を省略しない。
除外あり許可 chunk の隣接 graph と DFS を計算し、chunk 内 serpentine。runtime の walk は復旧可能な DFS。optimizedWalk は計算結果・見積互換として保持します。親子 anchor の許可辺、mine/transit lease、連結性を維持。採掘実行順を近道へ置換しない。
service routeshortestServiceRoute だけが補給・帰還の chunk path を BFS で求めます。service route も許可 chunk と transit lease の範囲内。チャンクロード状態で経路を変えません。
groupworld partition（stripe など）と stagger dispatch。assignment ごとに独立に集計。partial start は開始済みを safe return。local group は自動分割しない。
復旧・再開dock/home から保存 checkpoint へ shortestServiceRoute の BFS helper で戻り、state.db と journal を再検証。旋回中、GPS fix 不能、姿勢矛盾は blocked/wizard。
optimizedWalk は計算結果・見積互換であり、物理操作の省略ではありません。 runtime 実行順、chunk 間 transition、保護確認、checkpoint、復帰経路、帰還保証を飛ばす近道には使いません。

実装されている性能機構

adaptive service

fuel、seal、torch、空き slot の low watermark を見て、行末や帰還の境界で補給をまとめます。group では replenishConcurrency を超えて同時 service しません。

render cache

controller の grid／worker 行の描画をキャッシュし、入力や status が変わったときだけ更新します。表示を速くするだけで、採掘経路は変えません。

stack compression

seal 許可 block の同名 stack を reserved slot 以外でまとめ、空き slot を確保します。圧縮失敗時は discard や掘削を強行しません。

checkpoint cadence

軽量 checkpoint、journal、GPS verify を move 範囲で分け、毎 block の network round-trip を避けます。状態正本は state.db です。

絶対 BOTTOM Y の計算と速度

world job の深さは相対 depth ではなく、calibrated homeY と絶対 BOTTOM Y から求めます。

depth = homeY - targetY + 1
targetY = bottomY（world queue / group）
  • targetY は homeY 以下でなければ fatal。
  • group の全 worker が同じ bottomY を受け取り、worker ごとの layers は homeY に応じて計算。
  • homeY、GPS、bay pose が不明なら world preflight は開始しない。
  • local queue は入力した depth を使い、BOTTOM Y／world overlap は使わない。

見積と実績

PREVIEW の見積は dimensions、許可 cells、経路、profile、設定済み補給を前提にした概算です。以下は差が出やすい項目です。

差分要因影響調整
水・溶岩 seal設置、連続上限、補給帰還。SAFE または BALANCED、seal reserve を増やす。
保護／Mod block掘れずに迂回・停止。protectedBlocks と小さな試験区画。
torchniche 探索、補給、設置失敗。専用 torch chest、間隔、照明 mode を確認。
discard／仕分けinventory route と chest の待ち時間。report の discard、throughput、waiting_* を比較。
GPS／通信verify cadence、fix timeout、retry。host 距離・ロードを管理者側で調整。

完了後は report の estimate と actual、fuel、seal、torch、discard、throughput、lastReturn を並べ、同じ dimension・同じ profile で比較します。

安全なチューニング手順

  1. バックアップしたワールドで小さい BALANCED job を完了させ、baseline report を保存。
  2. 一度に 1 つだけ（照明間隔、fuel buffer、compact cadence、discard threshold）を変更。
  3. waiting_fuel／waiting_seal／waiting_torch、return distance、throughput を比較。
  4. 速度向上が return／安全境界を削らないことを確認。TURBO は fuel safety を下げない。
チャンクロード状態は測定値として取得できません。サーバー側のロード設定と CC Miner の throughput を混同しないでください。
