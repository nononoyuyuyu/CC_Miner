# 6. トラブル復旧

## 最初に見る情報

ワーカー側:

```text
ccm status
ccm logs
```

コントローラ側:

```text
ccm discover
```

ダッシュボードでは対象を選び、`I` を押すと状態、phase、座標、燃料、空きスロット、エラーを確認できます。

## ワーカーが見つからない

確認順:

1. ワーカー画面に `No wireless modem found` が出ていないか。
2. ワーカーにWireless Modemアップグレードが付いているか。
3. コントローラの隣にWireless Modemがあるか。
4. 両方のネットワークキーが完全一致しているか。
5. 両方が同じディメンションか。通常モデムでディメンション越し通信はできません。
6. 距離が通信範囲内か。
7. ワーカーのチャンクがロードされているか。
8. コントローラで `D` または `ccm discover` を実行したか。

キーを直す場合、各機械で:

```text
ccm setup
reboot
```

## `waiting_output`

原因:

- 搬出チェストが真後ろにない
- チェストの位置を変更した
- 搬出チェストまたは下流倉庫が満杯
- MODコンテナが汎用インベントリとして認識されない

復旧:

1. ワーカーを動かさず、後方1ブロックを確認します。
2. 通常ChestまたはBarrelを正しい位置へ置きます。
3. 空きを作ります。
4. コントローラで `R`、または `ccm resume <ID>` を実行します。

## `waiting_fuel`

原因:

- 燃料チェストが真上にない
- 燃料チェストが空
- 先頭に非燃料がある
- サーバ設定で想定したアイテムが燃料ではない

復旧:

1. 真上1ブロックのチェストを確認します。
2. 非燃料をすべて取り除きます。
3. 有効な燃料を入れます。
4. `R` または `ccm resume <ID>` を実行します。

プログラムは非燃料を消費せず、可能なら燃料箱へ戻します。

## `blocked` と主なエラー

| エラーの一部 | 意味 | 対応 |
|---|---|---|
| `lava:` | 正面・上下に溶岩 | 周囲を安全化後 `resume`、またはジョブ中止 |
| `protected:` | Bedrock、ポータル、コンピュータ等 | 対象を避ける。Bedrock下向きは正常完了扱い |
| `protected_inventory:` | チェスト・倉庫・Vault等 | 設備を移すか、採掘範囲を変更 |
| `inventory_full` | 空きスロット0 | 原因を確認しRecallまたは物理復旧 |
| `out_of_fuel` | 帰還計算前に燃料0 | 原則は起こらない。位置を変えずに燃料投入可能なら補給 |
| `path_desync` | 保存座標と次セルが隣接しない | 手動移動または状態破損。Rehomeが必要 |
| `Movement failed` | 生物、保護、落下ブロック、権限等 | 障害物を除去して `resume` |
| `recovery_required` | 物理命令中に電源断 | 下記の物理復旧を実行 |

## 物理位置が不明な場合

`recovery_required`、手で壊した、ピストンで移動した、向きを変えた場合は自動再開しません。

### 復旧手順

1. ワーカーのインベントリを必要に応じて回収します。
2. ワーカーを元のドックへ置きます。
3. 後方が搬出チェスト、上方が燃料チェストになる位置へ合わせます。
4. 正面を採掘方向へ向けます。
5. コントローラで対象を選び `G` を押します。
6. 画面の注意を読み、`RESET` と入力します。

コマンドラインなら:

```text
ccm rehome <ID> RESET
```

コントローラへ通信できない場合は、ワーカー画面で `Ctrl+T` を長押ししてプログラムを停止し、物理配置と向きを直してからワーカー自身で実行します。

```text
ccm rehome RESET
reboot
```

この操作は座標を `(0,0,0,dir=0)` へ戻し、現在のジョブ、チェックポイント、復帰情報を消去します。同じジョブの継続はできません。

## 一時停止から戻らない

- 採掘地点でPauseした場合: `R` でその場から継続します。
- Recall後にホームでPauseした場合: `R` でチェックポイントへ戻ります。
- サービス途中にPauseした場合: `R` で帰還・補給・復帰の途中から継続します。

`I` で `phase` を確認してください。

## コントローラだけ止まった

ワーカーは自律処理を継続します。コントローラで:

```text
ccm dashboard
```

または:

```text
reboot
```

再検出後、最新状態が表示されます。

## HTTPが無効

`HTTP API is disabled`、`Domain not permitted`、`wget: Failed` の場合:

- サーバ管理者にComputerCraft HTTP設定と許可ドメインを確認する
- または [オフライン導入](03-install.md#b-オフライン導入) を使う

許可する接続先は、このシステムでは `raw.githubusercontent.com/nononoyuyuyu/CC_Miner` だけです。

## 更新後に起動しない

旧版へ戻す前に:

```text
ccm logs
```

を確認します。旧コードが `/ccminer.backup` にある場合、ホームで停止した状態で次を実行できます。

```text
delete /ccminer
move /ccminer.backup /ccminer
reboot
```

状態ファイルも旧ディレクトリ側に残るため、更新直前の構成へ戻せます。

## 既存startupが邪魔をする

インストール前のstartupは `/startup.user.lua` に保存されます。そのファイルが入力待ちや永久ループをするとCC Minerが開始しません。

一時的に無効化:

```text
move /startup.user.lua /startup.user.disabled
reboot
```

必要な処理だけを後で整理して戻します。

## ログ容量

`/ccminer/data/ccminer.log` は約64KBでローテーションし、前世代を `ccminer.log.1` に残します。`ccm logs` は直近30行を表示します。
