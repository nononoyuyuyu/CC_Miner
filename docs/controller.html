controller と dashboard

ccm dashboard は worker の状態を discover し、端末と Advanced Monitor に同じ画面を描画します。マウス、monitor_touch、キーボードは同じ操作処理へ入ります。

テキスト代替：左列が worker と操作、右が選択 worker の詳細、下がキーボード一覧。小さい monitor は端末を使います。

discover と worker 行

  1. controller と worker の network key が同じ、Wireless Modem が有効であることを確認。
  2. ccm discover または DISCOVER を押す。
  3. worker 行で status、progress、layer、fuel、seal、torch、waiting reason、GPS calibrated を確認。
  4. offline／timeout は chunk load の証拠ではありません。通信距離・dimension・server 側 load を別に確認します。

NEW JOB と preflight

  1. worker を選び、幅 W（右）、長さ L（前）、深さ D（下）を入力。
  2. SAFE／BALANCED／TURBO、waterMode／lavaMode、照明、採掘石再利用、通知を選択。
  3. CHUNK GRID で ALL／CLEAR／RECT／INVERT／個別を設定。入口は固定。
  4. PREVIEW → PREFLIGHT。fatal が 0 のときだけ START または QUEUE。stock／fuel／seal／torch 不足は補給前提 warning。
  5. world queue を使う場合は GPS 校正済み worker を選択し、絶対 BOTTOM Y の targetY を入力。
画面できること注意
PRESETSAFE / BALANCED / TURBO と保存済み job を読み書き。保存値と実効値を preflight で確認。
QUEUE独立 job を worker ごとの順番で保持・dispatch。world X/Z 重複は拒否。単一 footprint 分割は不可。
HISTORY / REPORTjobId、reason、time、elapsed、progress、stats、estimate／actual、materials。完全な監査ログではない。
INFOGPS、経路、fuel、在庫、seal、torch、journal。chunk load 状態は表示しない。

停止・復旧操作

PAUSE / RESUME

安全境界で一時停止。停止中は在庫と state を確認してから RESUME。

STOP

即時、行末、層末、帰還、中止を選択。物理操作途中での急停止はしません。

RECALL / SERVICE

帰還して搬出・fuel・seal・torch を補給。unloading boundary を保存。

RECOVER / REHOME

復旧 wizard を優先。REHOME RESET は物理的に home へ戻した後だけ、job を消す二段確認です。

通知と Wired Modem 仕分け

speaker／redstone は完了・停止・待機・復旧要求の通知だけに使います。controller の Wired Modem は source inventory から valuable／bulk／seal へ push します。送出先が満杯または切断中なら source に残し、次 tick に再試行します。これは worker の waiting_output と直結せず、外部装置の二重処理も保証しません。

通知信号でドア、ピストン、ポンプ、チャンクローダーを直接制御しないでください。CC Miner に権限管理はありません。

controller 側の保持

ACK/status、queue、lease、preset、history を controller DB に保存します。送信失敗は再試行しますが、電源断後に外部 inventory の push を完全に一度だけにする仕組みではありません。state.db は worker 側の正本です。

GROUPS が空のとき：registry を登録

dashboard の GROUPS 画面に No groups と出る場合、controller 端末で 1 つの管理 dock、各 worker の独立 bay、group を順に登録します。登録後に ccm group list と GROUPS を再表示してください。

ccm dock register dock-a 100 64 100 east 64
ccm bay register bay-a 100 64 100 east 64
ccm bay register bay-b 116 64 100 east 64
ccm group register quarry-a 101,102 QuarryA dock-a bay-a world stripe 101=bay-a,102=bay-b 101=dock-a,102=dock-a

group の完全な構文は ccm group register <id> <workerIds comma> [name dock bay mode partition workerBayMap workerDockMap]。map は workerId=resourceId,...（空白なし）で、上例の末尾が workerBays と workerDocks です。座標は整数、facing は front/south=0、right/east=1、back/north=2、left/west=3（または 0〜3）、maxDepth は正の整数です。

START 前の必須条件。 world group は各 worker の home／正面 1 ブロック先が同じ自分の bay chunk、worker 間 bay chunk が一意、全 bay chunk が共通 footprint 内、same-floor の HOME Y、GPS forward orientation が揃う必要があります。例の x=100 と x=116 は別 chunk です。bay chunk の重複や footprint 外、floor／facing 違反は preflight fatal。詳細は group 登録 と 物理配置 を参照してください。
