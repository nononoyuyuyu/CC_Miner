# 0. 概要と座標の考え方

## このシステムでできること

CC Miner V2は、採掘タートルを1台以上、拠点コントローラを1台置き、コントローラから採掘寸法を入力すると、指定した直方体を自動採掘するシステムです。

採掘中にインベントリまたは燃料が少なくなると、タートルは自分でホームへ戻ります。後方チェストへ搬出し、上方チェストから燃料を補給した後、保存済みの採掘地点へ戻って続きを実行します。

![システム全体図](images/system-overview.svg)

## 用語

| 用語 | 意味 |
|---|---|
| ワーカー | 実際に採掘する、つるはし・無線モデム付きAdvanced Turtle |
| コントローラ | ワーカーを検出し、ジョブ開始や帰還を指示するAdvanced Computer |
| ホーム／ドック | ワーカーを最初に置く座標。搬出・補給・復旧の基準点 |
| 搬出チェスト | ホームでタートルの真後ろに置くチェスト |
| 燃料チェスト | ホームでタートルの真上に置くチェスト |
| チェックポイント | 自動帰還前に保存した採掘位置・向き |
| ジョブ | 幅、長さ、深さを持つ1回の矩形採掘作業 |

## 座標と寸法

ホームを `(x=0, y=0, z=0)` とします。タートルを置いた時の正面が `+Z`、右が `+X`、上が `+Y` です。

- **幅 W**: タートルから見て右方向へ何列掘るか
- **長さ L**: タートル正面から前方へ何ブロック掘るか
- **深さ D**: 下方向に何層掘るか

重要な点として、`D=1` は「タートルと同じ高さの1層」です。`D=2` なら同じ高さと、その1ブロック下の合計2層です。

最初に掘るブロックは、ホームにいるタートルの正面1ブロック目です。ホームそのものは採掘範囲に含みません。

## 採掘経路

各層を前後に蛇行し、層の終端で1ブロック下降します。次の層では経路を反転するため、すべてのセルが必ず隣接し、不要な長距離移動を挟みません。

![クアリー採掘経路](images/quarry-path.svg)

進捗 `cursor` は、採掘済みセル数です。たとえば `8 × 32 × 16` の総セル数は `4096` です。

## 自動帰還の流れ

1. インベントリ空きスロットまたは燃料を毎セル確認します。
2. 帰還が必要になると、現在の位置・向き・ジョブ進捗を保存します。
3. 既に通過した経路を使ってホームへ戻ります。
4. 搬出チェストへ全スロットを排出します。
5. 燃料チェストから有効な燃料を1個ずつ取り、設定値まで補給します。
6. 帰還経路を逆順にたどってチェックポイントへ戻ります。
7. 次のセルから採掘を再開します。

## 状態の意味

| 状態 | 意味 | 人が行うこと |
|---|---|---|
| `idle` | ジョブなし、ホーム待機 | 新規ジョブを開始可能 |
| `working` | 採掘、帰還、搬出、補給、復帰中 | 通常は触らない |
| `paused` | 位置とジョブを保持して停止 | `resume` または `recall` |
| `waiting_output` | 搬出先がない、または満杯 | 搬出チェストを直し、`resume` |
| `waiting_fuel` | 燃料箱がない、空、異物入り | 燃料を直し、`resume` |
| `blocked` | 溶岩、保護対象、移動不能、状態不整合 | 原因を除去後 `resume`。位置不明なら `rehome` |
| `complete` | 採掘完了してホームへ帰還済み | 結果確認後、新規ジョブまたは `clear` |
| `aborted` | 中止してホームへ帰還済み | 再開不可。新規ジョブまたは `clear` |

## 想定する完成形

- ワーカー1台につき専用ドック1組
- コントローラ1台で複数ワーカーを監視
- 各ワーカーの採掘範囲は重ねない
- 搬出チェスト以降の物流は、必要に応じてCreateのFunnel、Chute、Belt、Item Vault等へ接続
- コントローラ横のAdvanced Monitorは任意。なくても全機能を操作可能
