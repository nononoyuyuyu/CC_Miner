# 00. 全体設計（V3）

CC Miner V3 は、採掘タートルを「永続化された状態機械」として扱います。コントローラーはジョブ定義と停止要求を送信し、ワーカーは移動・採掘・封鎖・搬出・補給の境界を journal と状態ファイルへ記録します。コントローラーが一時的に切断されても、ACK/status の保持と再試行で状態取得を続けますが、外部装置の二重処理を保証するものではありません。

![V3 のコントローラー、GPS、ワーカー、ドック、採掘領域](images/system-overview.svg)

## 構成要素

### ワーカー

Advanced Mining Turtle と Wireless Modem で動作します。ドックをローカル `(0,0,0)`、正面を `+Z`、右を `+X`、下を `-Y` とします。除外なしでは全セルを一度ずつ通る蛇行経路、除外ありでは許可チャンクの連結 DFS とチャンク内蛇行を使います。

ワーカーは以下を担当します。

- 採掘前 preflight、燃料・在庫・封鎖材・たいまつの見積と補給判断
- 設定された照明間隔でのたいまつ設置。SAFE は最大 8 moves、BALANCED は設定値（既定 10）、TURBO は 12。明示した `waterMode` / `lighting.mode` はプロファイルで上書きしません
- 採掘石のうち許可リストにある固体ブロックを封鎖材として保持・再利用
- 水／溶岩の検知、封鎖、連続封鎖上限到達時の停止
- 行末・層末・帰還などの段階停止、アンロード境界、復旧 wizard 用のチェックポイント

### コントローラー

Advanced Computer と Wireless Modem でワーカーを発見し、端末または Advanced Monitor へ同じ画面を描画します。ワーカー行、ジョブ寸法、チャンクグリッド、preflight、キュー、履歴、レポートをタッチ／クリックまたはキーボードで操作します。

### GPS ホスト

`gps` 役割は組み込みの `gps host` を起動します。GPS は任意ですが、ワールド座標チャンク、GPS 必須モード、電源断した移動の自動判定には 4 台以上のホストと校正が必要です。GPS がない場合はローカル座標で動作し、ワールド座標グリッドは選べません。

![高さを変えた GPS ホストの配置例](images/gps-layout.svg)

GPS は位置を測るだけで、向きはドックでの 1 ブロック往復から保存します。GPS の fix 取得は環境依存で、チャンクロード状態の取得やロード操作には使いません。

### ドックと任意の物流

搬出・燃料・seal 材を基本の 3 系統とし、torch チェストは seal 側の反対側に専用で置きます（既定 seal=右、torch=左）。有線仕分けは任意で、controller が source inventory から valuable／bulk／seal へ push します。満杯時は残留して次 tick に再試行し、worker の `waiting_output` とは直結しません。speaker と redstone は完了・停止・待機などの通知だけに使い、採掘の権限管理は行いません。

## ジョブのライフサイクル

1. **作成** — 寸法、チャンク操作、液体動作、照明、SAFE/BALANCED/TURBO、通知を入力し、必要ならプリセットへ保存します。world queue の `targetY` は GPS 座標だけで有効で、`depth = homeY - targetY + 1`、local queue は入力した depth を使います。
2. **preflight** — 接続、入力、連結性、能力、lease、GPS 条件、範囲の重複を検査します。stock 不足は補給前提の warning、offline／invalid／connectivity／capability／lease は fatal です。
3. **見積** — 体積、採掘セル、移動距離、想定補給回数、封鎖材・たいまつ予備を表示します。Mod 追加ブロックや実際の迂回は見積に含まれない場合があります。
4. **実行** — 許可チャンクだけを通る経路で採掘します。各物理操作の前後を状態と journal に保存します。
5. **段階停止／サービス** — `pause_now`、行末、層末、帰還、中止から選べます。搬出・燃料・封鎖材補給中に停止しても、アンロード境界を再ロード後に再検証して続行します。
6. **完了／復旧** — 完了時はジョブ履歴と、`jobId`、`reason`、`time`、`elapsed`、`progress`、`stats`、`estimate`／`actual`、material counts を持つレポートを保存します。GPS で解決できない旋回や位置不一致は復旧 wizard を表示し、ドックへ戻して REHOME するまで再開しません。

## チャンクグリッドと範囲管理

![入口を残したチャンク選択例](images/chunk-mask.svg)

グリッドは 1 タイル = 1 チャンクです。GPS 校正済みではワールドチャンク座標、未校正では採掘原点基準の相対チャンクを表示します。入口チャンクは常にロックされ、部分セルはありません。

- 初期状態と **ALL** は全チャンクを採掘対象
- **CLEAR** は入口以外を解除
- 個別タッチで採掘／解除を切り替え
- **RECT** は二点で囲んだ矩形だけを採掘対象
- **INVERT** は入口を固定したまま反転
- 色で入口、採掘対象、除外、採掘済み、現在進行中、停止／エラーを表示

開始前に許可チャンクの連結性を検査し、入口から到達不能な領域を拒否します。world queue は active／queued の X/Z 範囲重複を拒否し、local queue は指定 worker ごとの順番で処理します。単一 footprint を複数 worker へ分割する機能は安全上無効です。複数 worker は非重複な独立 queue job を dashboard 稼働中に並列 dispatch します。

## 永続化と速度

完全な状態は `/ccminer/data/state.db`（および `.bak`）を正とし、journal と定期 checkpoint は補助です。journal は `maxEntries`／size rotate と checkpoint で抑制し、書けない場合も状態ファイルを優先します。通常 serpentine は高速に歩き、除外時は DFS とグラフ計算、adaptive service、render cache、stack compression を高速化します。未使用の `optimizedWalk` で経路を省略することはありません。

## 通信と制約

全メッセージにプロトコル、スキーマ、バージョン、ネットワークキー、送受信元、メッセージ ID を含め、ACK/status を保持して再試行します。これは通信の再送を扱う仕組みであり、外部チェストや仕分け機の二重処理を保証するものではありません。ネットワークキーは暗号化・強い認証ではありません。管理者ロール、権限分離、チャンクローダーの検出・表示・自動化は V3 の対象外です。
