# 7. 検証内容

通常利用者がテストコードを書く必要はありません。インストーラはダウンロード直後に全Luaファイルを構文検査し、ワーカーはジョブ開始前に搬出・燃料設備を確認します。

このリポジトリでは、次の検証を一括実行できます。

```text
make test
```

## 自動検証項目

- 全Luaソースの構文読み込み
- 生成したオフライン一括導入版の構文読み込み
- 幅1～6、長さ1～7、深さ1～4を含む採掘経路の全セル検証
- 各セルが範囲内で一度だけ現れること
- 連続するセル間のマンハッタン距離が必ず1であること
- `manifest.lua`、オンラインインストーラ、オフライン生成器の配布対象一致
- Markdown内の相対リンクと画像の存在
- 許可された `nononoyuyuyu/CC_Miner` 以外のGitHub URLが含まれないこと
- 配布ファイルの生成再現性とサイズ上限

## 実装上の検証ポイント

### 採掘経路

`src/ccminer/lib/quarry.lua` は、入力寸法と0始まりのセル番号から座標を決定する純粋関数です。過去の移動履歴へ依存しないため、再起動後も同じ `cursor` から同じ座標を復元できます。

### 帰還経路

ホームへの経路は `Y → X → Z`、チェックポイントへの復帰はその逆の `Z → X → Y` です。復帰時に未採掘の行を横切らないようにしています。

### 燃料

補給目標は、設定値と次の安全必要量の大きい方です。

```text
2 × ホームからチェックポイントまでの距離 + fuelBuffer
```

これにより、チェックポイントへ戻った直後でも、再度ホームへ帰還する燃料を確保します。

### 電源断

回転・移動・採掘前に物理動作ジャーナルを保存します。成功後にジャーナルと新座標を同じ状態保存へ反映します。中間で停止した場合は、自動継続せず復旧要求となります。

## 実Minecraft環境について

このリポジトリ上の検証は、Lua構文、状態遷移の静的確認、採掘経路シミュレーション、配布整合性を対象とします。実際のMinecraftサーバでは次が外部条件です。

- Create: Astralの正確なKubeJSレシピ
- ComputerCraft HTTP許可設定
- チャンクロード方式
- サーバの燃料設定
- 保護プラグインやClaim
- MODコンテナの汎用インベントリ実装
- ワールド内の流体、重力ブロック、他プレイヤーやMob

そのため、利用者がコードを調整したり開発テストを行う必要はありませんが、手順書どおりの配置、REIでのレシピ確認、チャンクロード、十分な燃料・空き容量は必要です。
